# Авто-МП

Локальное приложение для переноса медиапланов из Excel и факта из DataLens в AGM Core с предварительным просмотром и построчной сверкой.
Интерфейс поддерживает тёмную и светлую темы; выбор сохраняется в браузере.

## Запуск

1. Windows: установи Node.js 20+, npm и Python 3, затем запусти `start.cmd`. Ubuntu: установи Node.js 20+, npm, Python 3 и `sudo`, затем запусти `bash start.sh` из каталога приложения. Скрипт установит npm-зависимости и Chromium для Playwright при первом запуске; если не хватает системных библиотек Chromium, установит их через `sudo`.
2. Открой `http://127.0.0.1:8765`.
3. Подключи Chromium, управляемый приложением через Playwright. Страница CRM показывается внутри окна приложения.
4. Введи ссылку на конкретный медиаплан Core и/или ссылку на конкретный отчёт DataLens. Фильтры, включая период, пользователь выставляет в отчёте; приложение их не угадывает.
5. Загрузи Excel и выбери нужный лист, если переносишь план. Если в указанном отчёте DataLens несколько таблиц, выбери нужную таблицу.
6. Считай МП и источник, проверь список изменений и расхождений. Приложение внесёт значения в открытую форму Core как несохранённый черновик; после проверки черновика нажми отдельную кнопку подтверждения сохранения.

Поддерживаются сценарии Excel → прогнозный план, DataLens → фактический план и Excel + DataLens → оба представления МП. Ссылки должны вести на нужные страницы AGM Core и DataLens.

## Проверки и ограничения

- Excel читается без изменения исходной книги.
- При чтении HTML-таблиц Core и DataLens приложение разворачивает объединённые ячейки строк/столбцов в прямоугольную сетку, чтобы значения не сдвигались в соседние поля.
- Факт сопоставляет «Описание» строки МП с «Объектом продвижения» DataLens. Нормализация пробелов и пунктуации применяется для всех имён; префикс «ЛСР» снимается, «Лейк» и `Lake` считаются эквивалентными. Пропущенные и неоднозначные связи блокируют перенос.
- Показы из отчёта переводятся из штук в тысячи для полей МП. Допуск для итоговых сумм — ±10 ₽; лиды сверяются точно.
- Для плана CPM берётся из цены за единицу, для FIX-бюджета — из стоимости без АК; клики рассчитываются Core и только сверяются с округлённым прогнозом. Сверка процентов и показов учитывает точность отображения соответствующих полей.
- При импорте Excel программа выбирает название размещения по описанию кампании/строки; если его нет — по типу семантики/категории, а не по общему названию объекта. Строки-разделы без формата расчётов пропускаются, модели `CPC`/`CPM`/`CPA`/`FIX` распознаются с учётом кириллических букв, а `STATIC` и неизвестные модели остаются без изменений и показываются в предупреждениях предпросмотра.
- АК выставляется вручную. Программа пропускает любое поле АК до сопоставления колонок, в том числе при совпадающих заголовках и описаниях агентской комиссии/вознаграждения; сервер также блокирует такие поля при подготовке записи и построчной сверки. AdRiver и Botfaqtor исключены из изменений и сверки.
- Перед внесением приложение показывает каждую изменяемую ячейку и список проблем сопоставления. Предпросмотр только читает Core. `/api/apply` заполняет форму как несохранённый черновик и никогда не нажимает кнопку Core «Сохранить». После отдельного действия пользователя и подтверждения диалога интерфейс вызывает `/api/save`; сервер отклоняет этот запрос без явного подтверждения и проверенного черновика.
- Перед применением МП и выбранная таблица DataLens перечитываются для проверки, что данные не изменились после предпросмотра.
- При подготовке записи сервер повторно вычисляет каждое ожидаемое значение сверки из исходной ячейки Excel/DataLens и проверяет её строку и колонку; ожидаемые значения нельзя подменить отдельно от источника. Для Excel сервер также сверяет группу размещения, модель расчёта и разрешённые метрики, включая ограничение CPL/лиды для классифайдов.
- Перед записью сервер независимо восстанавливает полный набор ожидаемых пар «строка МП × показатель» по источнику, модели размещения и правилам исключений. Если клиент прислал неполный/лишний набор проверок или в источнике пустое/нечисловое значение, запись блокируется.
- После подтверждённого сохранения приложение перечитывает МП и проверяет связанные ячейки построчно и агрегированные суммы. Если сохранение или сверка не подтверждены, результат отображается как ошибка.
- Когда в явно указанном отчёте найдено больше одной таблицы, приложение не выбирает первую автоматически.

Период и фильтры выставляются вручную. Точное сопоставление в режиме плана зависит от совпадения названий строк; неизвестные или повторяющиеся строки не угадываются и требуют проверки.

Строки МП, которых нет в выбранном источнике, выводятся отдельным предупреждением и остаются без изменений; пропущенные строки источника и неоднозначные соответствия блокируют перенос.

## Локальные данные и авторизация

По умолчанию сервер слушает только `127.0.0.1`; публичный запуск требует настроенной HTTPS-публикации и хотя бы одной учётной записи администратора. Обычная работа не показывает окно авторизации: сервер выдаёт каждому браузеру отдельную защищённую cookie-сессию, профиль Chromium, книгу и временные данные. Администратор входит отдельно из панели обратной связи; его роль проверяется сервером, а сессия админ-панели автоматически истекает через 30 минут. Playwright и Python берутся из обычных зависимостей и системного PATH, профили ChatGPT Work и локального Chrome не используются.

Для публикации используй HTTPS reverse proxy перед Node.js и задай `AGM_HOST=127.0.0.1`, `AGM_PUBLIC_ORIGIN=https://...`, `AGM_ALLOWED_HOSTS=...`, `AGM_USERS_FILE=...` и `AGM_DATA_DIR=...`. Не публикуй порт Node.js напрямую. Сессии браузера закрываются при уходе со страницы приложения и простаивают до 60 минут; одновременно разрешено до 18 контекстов Chromium (`AGM_MAX_BROWSERS`, максимум 18). Учётные записи администраторов читаются при старте, поэтому после добавления/удаления пользователя сервер надо перезапустить.

Сообщения формы обратной связи дописываются в общий `feedback.jsonl` с ограниченными правами на чтение. Любой сотрудник может пользоваться приложением без браузерного окна входа; отдельный профиль автоматически создаётся для его сессии браузера. Администратор вручную входит внизу страницы и видит последние 500 обращений, новые сверху; без входа этот API недоступен. Создай администраторскую учётную запись командой `node scripts/users.mjs add ИМЯ --admin`; пароль вводится интерактивно без эха. Для смены роли используй `node scripts/users.mjs role ИМЯ admin|user`; после правок списка учётных записей перезапусти сервер.

Пошаговая установка, systemd и nginx для Ubuntu 24.04 описаны в [`deploy/ubuntu-24.04.md`](deploy/ubuntu-24.04.md). Автономность Ubuntu в текущем Windows-окружении ещё не подтверждена реальным запуском Linux; инструкции содержат команды для воспроизводимой проверки на VPS.

Для чистого архива исходников без пользовательских данных выполни `npm run package:source`. Архив появится в `dist/agm-plan-assistant-source.tar.gz`; сборщик включает приложение, тесты и инструкции деплоя, затем проверяет архив на отсутствие `data/`, профилей Chromium, Excel-загрузок, `node_modules` и `.env`.

## Автономные проверки

`npm test` проверяет headless Chromium (DOM, ввод и клик), обработку объединённых ячеек и вложенных таблиц, независимое восстановление полноты проверок для плана и факта, допуск итоговых сумм и точность лидов, чтение XLSX системным Python, хэшированную авторизацию, изоляцию пользователей и отправку обратной связи. Полные потоки Excel→Core и DataLens→Core (предпросмотр, внесение несохранённого черновика, отказ сохранению без аппрува, подтверждённое сохранение и повторное построчное чтение) прогоняются на локальных HTML-фикстурах; реальные Core и DataLens не открываются. `npm run measure:resources` измеряет дерево RSS Chromium и приблизительную загрузку CPU на 1, 2 и 3 параллельных браузерах, используя `/proc` в Linux и `Win32_Process` в Windows. Синтетический замер помогает сравнивать нагрузку, но не заменяет повторный прогон на целевом VPS: результаты зависят от RAM/vCPU и нагрузки машины.

Последний Windows-замер (12.10.2026, AMD Ryzen 5 6600H, 12 логических CPU, 15,2 ГиБ RAM):

| Одновременных браузеров | RSS дерева Chromium | CPU, ядра примерно |
| ---: | ---: | ---: |
| 1 | 205 МиБ | 0,074 |
| 2 | 490 МиБ | 0,186 |
| 3 | 635 МиБ | 0,327 |

Каждый браузер в течение пяти секунд снимал страницу и читал DOM раз в полсекунды. RSS — сумма working set процессов Chromium, включая разделяемые страницы памяти; используй её как грубую верхнюю оценку, а не точный объём уникальной RAM. Это не замер Ubuntu и не нагрузочный тест рабочих сайтов. Перед выбором размера VPS выполни тот же `npm run measure:resources` на целевой машине.
